# GD32 HAL Compatibility Layer 0.8.0 架构审查

审查日期：2026-08-24
审查对象：仓库初始提交 `bd344c9`，版本 `0.8.0`
目标器件：STM32F401VEH6 HAL 应用语义迁移到 GD32F403RET6 SPL V3.0.3

## 1. 审查基线与边界

本报告记录 0.9.0 修改前的 0.8.0 状态。审查依据为：

- 本仓库 `Inc/`、`Src/`、`Port/`、`Tests/` 和现有文档；
- 本地 STM32F4 HAL 官方驱动中的 Core、GPIO、UART、DMA、TIM、ADC 公开接口与 Handle 形状；
- GD32F403 SPL V3.0.3 的 GPIO、USART、DMA、TIMER、ADC、RCU 源码和头文件；
- `GD32F403_User_Manual_Rev3.1.pdf` 与 `GD32F403xx_Datasheet_Rev3.1.pdf`。

审查未包含真实 GD32F403RET6 板级测试。修改前执行 `Tests/run_checks.ps1`，ARM 对象严格编译、官方 SPL 目标链接、Clang Analyzer 和全部 Host Mock 均通过；这些结果只证明代码级基线可回归，不证明实际波形、时序、IRQ 延迟或模拟精度。

## 2. 当前架构

0.8.0 已形成三层雏形：

```text
Application
    |
Inc/stm32f4xx_hal_*.h
    |
Src/stm32f4xx_hal_*.c
    |
Port/gd32_hal_*_port.c + gd32_hal_port.h
    |
GD32F403 SPL / CMSIS（由产品工程提供）
```

HAL 函数主体大多通过 `GD32_HAL_*` Port 函数访问硬件，没有把 STM32 寄存器字段直接套到 GD32 寄存器上。Port 层对 GPIO、USART、DMA、TIMER、ADC、RCC 等做了 SPL 调用转换，并通过错误钩子拒绝一部分不可等价能力。

但边界并未真正闭合：

- `stm32f4xx_hal_def.h` 直接包含 `gd32_hal_port.h`，使所有公开 HAL 头文件传递依赖 GD32 CMSIS/SPL；
- GPIO/UART/TIM/ADC/DMA 公开 Instance 宏直接使用 GD32 外设地址；
- 公开 `__HAL_*` 宏直接调用 `GD32_HAL_*` Port API；
- `gd32_hal_port.h` 同时承担厂商头文件桥接、错误模型、全部模块 Port 类型、实例地址和函数声明，职责过大；
- `Inc/Src` 命名和 Port 文件名尚未达到目标目录约定，仓库也没有明确的 `CMSIS/`、`GD32_SPL/` 集成边界说明。

因此 0.8.0 是“已经有 Port 的兼容实现”，但还不是严格的“STM32 HAL Compatible API / GD32F403 Port / GD32 SPL”分层。

## 3. 已实现模块

| 模块 | 0.8.0 已实现范围 | 审查判断 |
|---|---|---|
| HAL Core | Init/DeInit、Tick、Delay、版本、UID、错误钩子 | 基础可保留；UID 地址和 SysTick 操作需继续限制在 Core/Port 边界 |
| GPIO | Init/DeInit、Read/Write/Toggle、EXTI 模式 | 常用数字/模拟模式较完整；AF remap 和输出 pull 已明确拒绝 |
| Cortex/NVIC | Priority、Enable/Disable、Pending/Active、SysTick、MPU 子集 | CMSIS 语义可保留；需要独立的 CMSIS 桥接边界 |
| UART | Init/DeInit、polling、IT、DMA、Abort、IRQ、weak Callback | 状态机和回调路径较完整；Instance/资源映射仍耦合地址 |
| DMA | Init/DeInit、Start、Start_IT、Poll、Abort、IRQ、Callback、请求冲突检查 | 已采用 GD32 Channel 模型；公开 Handle/宏仍残留 STM32 Stream 命名 |
| TIMER | Base/PWM/OC/IC/OnePulse、IT、DMA、Master/Slave、TRGO、ITR 转换 | 功能基础较强；触发映射文件和资源模型需重命名并集中化 |
| ADC | Init/DeInit、Channel、polling、IT、DMA、校准、序列、触发 | 基础能力已实现；Instance、触发映射和 ADC 资源字段需下沉到 Port |
| I2C/SPI | polling/IT，SPI 含 DMA | 超出 0.9.0 必需范围；架构改造中只做回归保护 |
| RCC/EXTI/FLASH | 有限安全子集 | RCC 保持常用门控和查询，不扩展成完整 STM32 RCC 模型 |

## 4. 重点设计检查

### 4.1 Handle 设计

优点：UART 保留了常用传输指针、计数、`hdmatx/hdmarx`、`gState/RxState/ErrorCode`；TIM 保留 `hdma[]`、Channel 和状态；ADC、DMA 都有独立状态及错误码。

问题：

- `Instance` 当前既表示 STM32 公开实例，又直接等于 GD32 寄存器基址，两个语义没有分开；
- Handle 没有稳定保存解析后的 GD32 资源，所有调用反复把 `Instance` 强转为地址；
- DMA 仍以 `DMA_Stream_TypeDef *Instance`、`StreamBaseAddress`、`StreamIndex` 命名 GD32 Channel，容易诱导上层按 STM32 Stream 思考；
- UART/TIM/ADC Handle 缺少显式的 GD32 instance、IRQ 和资源描述字段，无法在 Init 后固定映射并用于一致性检查；
- TIM Handle 没有 ErrorCode，部分 void 宏失败只能依赖全局错误钩子，问题定位粒度有限。

0.9.0 应保留 STM32 常用字段，并追加只由 Port 填充的资源字段。旧字段不删除，避免破坏常见应用源码和已有测试。

### 4.2 Instance 设计

当前实现会先 `#undef USART1/TIM1/ADC1/...`，再把 STM32 名称定义为 GD32 实际地址。例如 STM32 `USART1` 直接等于 GD32 `USART0` 地址。这避免了简单 `#define USART1 USART0` 的递归冲突，但仍是地址级机械映射：

- HAL API 层能看到 GD32 地址常量；
- `Instance` 无法区分“STM32 语义实例令牌”和“已解析 GD32 资源”；
- 不能集中执行器件/封装/IRQ/clock/DMA capability 校验；
- 未来扩展到同系列不同型号时需要修改多个公开头文件。

0.9.0 应新增 `stm32_hal_instance_map.h`，公开 STM32 语义令牌；Port 层把令牌解析为 GD32 地址、clock、IRQ 和 capability。禁止把 GD32 `USART0/TIMER0` 名称直接泄漏为 STM32 API 实例。

### 4.3 IRQ 设计

UART、DMA、TIMER、ADC 的 `HAL_*_IRQHandler()` 均检查标志和中断使能，并通过 HAL Callback 收尾；没有在 Port IRQ 文件中绕过 Callback。`gd32_hal_irq.c` 只提供 SysTick 转接，不抢占产品启动文件中的弱 IRQ 名称，这一原则正确。

差距：实例到 IRQn 的关系分散在公开头文件宏和 Port 常量中，Handle 未保存解析后的 IRQ；没有统一的“原生 GD32 ISR 调用对应 HAL IRQHandler”的文档模板。0.9.0 应把 IRQn 放入资源表，并在架构文档中明确共享 IRQ 的分发责任属于产品工程。

### 4.4 Callback 设计

UART/TIM/ADC Callback 使用独立 weak 定义文件，正常、半完成、错误和 Abort 路径有 Host Mock 与 ARM 弱符号检查。IRQ 没有直接调用业务函数，符合兼容层目标。

差距：运行时 Callback 注册在多数模块未实现并通过编译错误关闭；这可以保留，但必须在限制文档中标为“不兼容”，不能写成完全兼容。还需继续验证 normal/circular DMA 的状态更新与 Callback 次数。

### 4.5 DMA 设计

0.8.0 已正确拒绝 STM32 Stream 地址、FIFO、burst、PFCTRL 和 double-buffer；内部使用 GD32 DMA0 7 Channel、DMA1 5 Channel 模型，并按官方请求表检查固定物理 Channel 和请求冲突。

官方手册确认，同一物理 Channel 前的多个外设请求被硬件 OR，软件必须保证同一时间只启用一个请求。因此现有 Channel claim 机制应保留并增强，而不能模拟 STM32 Stream/Channel selector。

主要差距是公开类型和字段仍以 Stream 命名，且 `Init.Channel` 同时承载 GD32 请求令牌。0.9.0 应在 Handle 增加 `gd32_dma_periph`、`gd32_dma_channel`、request/resource 字段，明确 `Instance` 只是兼容令牌；FIFO/Burst 字段仅为源码编译兼容，非默认值必须返回 `HAL_ERROR`。

### 4.6 TIMER 设计

0.8.0 已实现按“STM32 ITR 源语义 -> GD32 目标 ITI 源矩阵”二次查表，不是直接把 ITR0..3 数值当 ITI0..3 使用。这一设计方向正确。

官方手册确认：GD32F403 全部 TIMER counter 均为 16 位；不同目标 TIMER 的 ITI0..3 源矩阵不同；部分 TIMER 不支持主从管理或互联。因此：

- TIM2/TIM5 的 STM32 32 位用法必须拒绝超出 `0xFFFF` 的配置；
- `stm32_timer_trigger_map.c` 必须按目标 Timer 和 STM32 ITR 语义解析，不允许全局固定表；
- TRGO、Slave mode、外部触发和硬件级联必须在 capability 表允许时才配置；
- 基础/PWM/OC/IC 可保留，Encoder、Hall、dead-time/break、DMA burst 不在 0.9.0 范围内。

当前文件名 `gd32_hal_timer_itr.c` 和地址驱动的表不符合目标命名与实例分层；0.9.0 需改为语义 Instance 驱动的 `stm32_timer_trigger_map.c`，再由 Port 使用 GD32 ITI 编码。

### 4.7 ADC 设计

0.8.0 已处理 12/10/8/6 bit、右/左对齐、1..16 rank、采样时间保守转换、regular polling/IT/DMA、启动校准和部分外部触发映射。

官方资料确认：

- ADC regular sequence 最多 16 个 rank；
- GD32 采样周期是 1.5/7.5/13.5/28.5/41.5/55.5/71.5/239.5 cycles；
- ADC0/1 外部触发源集合与 STM32F401 不同，且只接受上升沿；
- routine sequence 在整个序列结束时置 EOC，但 DMA 在每个 routine channel 转换结束时产生请求；
- GD32 需要复位校准并执行校准，不能照搬 STM32 ADC 启动流程；
- GD32F403 数据手册在 VREFP/VDDA 条件满足时给出 ADC clock 0.1..40 MHz。

现有触发转换位于 HAL 源文件，仍带有 GD32 枚举；Instance 也直接是 GD32 ADC0 地址。0.9.0 应把触发解析、校准和序列寄存器/SPL 配置全部固定在 ADC Port，并在 Handle 保存解析资源。

## 5. 存在问题

按产品风险排序：

1. **分层泄漏**：公开 HAL 头文件经 `stm32f4xx_hal_def.h` 直接依赖 `gd32_hal_port.h` 和 `gd32f403.h`。
2. **Instance 语义错误**：STM32 Instance 只是换名后的 GD32 地址，没有独立语义映射层。
3. **Port 聚合过度**：单个 `gd32_hal_port.h` 超过三万字节，混合所有模块类型、错误、地址、IRQ 和函数声明，长期维护容易产生跨模块耦合。
4. **Handle 资源不可追踪**：Init 后没有统一保存实际 GD32 address/IRQ/clock/channel/capability，难以做一致性审计。
5. **目录与目标不一致**：`Inc/Src` 尚未调整为 `Include/Source`；GPIO Port 混在通用 Port 文件；Timer trigger 文件命名不符合目标。
6. **兼容等级未统一**：已有文档描述了限制，但没有一份 0.9.0 统一表区分“完全兼容、接口兼容、不可兼容、GD32 扩展”。
7. **测试边界**：现有 Host Mock 很强，但没有真实板测试；不能把静态编译、Mock 或 ELF 链接写成量产完成。
8. **超范围模块干扰**：I2C/SPI/RCC/EXTI/FLASH 已有实现，架构调整时必须回归保护，但 0.9.0 不应继续扩张它们以挤占 Core/UART/DMA/TIMER/ADC 收口工作。

## 6. 与目标架构的差距

| 目标 | 0.8.0 | 0.9.0 调整 |
|---|---|---|
| HAL API 不知道 GD32 细节 | 公开 def/header 直接包含 Port 并使用 GD32 地址/API | 新增兼容层基础类型与 Instance map；公开实例使用语义令牌；硬件解析下沉 |
| 分模块 Port | 已有 UART/DMA/TIMER/ADC Port，GPIO 混在通用文件 | 拆出 `gd32_gpio_port.c`，统一目标命名 |
| GD32 资源进入 Handle | 主要靠 `Instance` 地址和零散字段 | 为 UART/DMA/TIM/ADC 增加解析后资源字段 |
| IRQ/Callback 统一 | HAL IRQHandler/weak Callback 已有 | 加入资源表、IRQ 文档和共享 IRQ 分发规则 |
| DMA 完全 GD32 化 | 内部基本完成 | 去除“Stream 就是地址”的语义，公开限制更明确 |
| TIMER ITR->ITI 自动转换 | 已有地址驱动二次查表 | 改为 STM32 Instance 语义驱动的专用 mapping 文件 |
| ADC 触发/校准/序列下沉 | Port 已做寄存器/SPL 操作，HAL 仍转换 GD32 枚举 | 触发和资源解析进一步下沉 |
| 目标目录 | `Inc/Src/Port`，无 vendor 边界目录 | `Include/Source/Port/CMSIS/GD32_SPL/Docs` |

## 7. 0.9.0 修改计划

修改遵循“保留可验证状态机，替换资源和层次边界”的原则，不复制 STM32 HAL 源码，不修改 GD32 SPL。

### Phase 1：HAL Core、GPIO、Tick、NVIC

- 将 `Inc/`、`Src/` 调整为 `Include/`、`Source/`，同步测试和文档路径；
- 新增 `stm32_hal_instance_map.h`，定义不透明 STM32 语义 Instance；
- 建立公共兼容类型/CMSIS 桥接与内部 GD32 Port 头文件边界；
- 拆出 `gd32_gpio_port.c`，GPIO HAL 只通过 Port 操作；
- 保留 GD32 原生系统时钟初始化，只提供兼容 Tick/NVIC 和常用 RCC 门控；
- 添加 Layer boundary、Instance map 和 GPIO 回归测试。

### Phase 2：UART

- UART Handle 保留 STM32 常用字段并增加 GD32 instance、IRQ、resource；
- 删除 0.8.0 对不存在于 STM32F401 的 `USART3/UART4/UART5` 假别名，只解析真实的 `USART1/2/6` 语义令牌；
- polling/IT/IRQ 全部使用解析资源；
- 保证 GD32 ISR -> `HAL_UART_IRQHandler()` -> weak Callback；
- 继续拒绝 oversampling 8；GD32 多出的 UART3/4 保留给原生 SPL，不伪装成 STM32F401 Instance。

### Phase 3：DMA

- 为 DMA Handle 增加 `gd32_dma_periph`、`gd32_dma_channel` 和 request/resource；
- 把物理 Channel、请求令牌、claim 和状态机集中到 `gd32_dma_port.c`；
- 保留 STM32 Init 字段用于源码编译兼容，但 FIFO/Burst/PFCTRL 非默认配置返回 `HAL_ERROR`；
- 验证 normal/circular、half/full/error、Abort、冲突和 Parent 绑定。

### Phase 4：TIMER

- TIM Handle 增加 GD32 instance、IRQ/resource/ErrorCode；
- 把 `gd32_hal_timer_itr.c` 重构为 `stm32_timer_trigger_map.c`；
- 映射输入采用 STM32 Timer 语义实例，输出为目标 Port 可用的 GD32 ITI；
- 保留 Base/PWM/OC/IC、IRQ、常用 counter/compare 宏；
- 严格拒绝 32 位范围、无互联能力和不可等价源。

### Phase 5：ADC

- ADC Handle 增加 GD32 instance、IRQ/resource；
- 将 trigger、resolution、sampling time、sequence 和 calibration 决策收口到 ADC Port；
- 保留 polling/IT/DMA 状态机；
- 验证 sequence EOC、每通道 DMA request、触发边沿和固定 DMA0 Channel 0 约束。

### 文档与发布

- 新增 `ARCHITECTURE.md`、`STM32_GD32_MAPPING.md`、`LIMITATION.md`、`TIMER_TRIGGER_MAPPING.md`、`DMA_DIFFERENCE.md`；
- 每个 API 标注完全兼容、接口兼容、不兼容或 GD32 扩展；
- 版本升级到 `0.9.0`；
- 全量运行 ARM 严格编译、官方 SPL 目标链接、静态分析和 Host Mock；
- 发布结论必须保留“待 GD32F403RET6 板级验证”，不得宣称量产签核。

## 8. 自检门禁

0.9.0 完成前必须逐项回答：

1. `Source/` 是否仍直接访问 STM32 寄存器或假设寄存器同构？
2. `CMSIS/`、`GD32_SPL/` 参考/集成目录中的官方文件是否保持未修改？
3. 是否有未完成操作返回 `HAL_OK`？
4. 是否定义了 GD32F403RET6 不存在的 FIFO、Burst、32 位 Timer 或 ADC trigger edge 能力？
5. IRQ 是否只处理已置位且已使能的来源，并经 HAL Callback？
6. DMA normal/circular/abort/error 状态和 Channel claim 是否闭合？
7. TIMER ITR 是否按目标实例查 GD32 ITI 矩阵，而不是直接复用编号？
8. ADC sequence、EOC、DMA、校准和触发是否符合 GD32 手册？
